1. 它们是什么关系

三篇论文共同回答一个问题：为什么把更多机器人数据放进同一个 VLA，仍不自然地产生跨本体能力？答案不是一个单独模块，而是不同层级的不一致会依次卡住 transfer。

CalibAll 位于数据入口：旧数据没有外参、EEF/TCP 定义不同，先把 action label 变成 camera-frame TCP。Qwen-RobotManip 位于 foundation model：用 canonical slots、camera-frame delta、history context、data curation 与 VL co-training 把对齐后的多源信号转成 scaling。Cloak 位于 observation 与 deployment：即使动作能 retarget，wrist view 里新夹爪/新手的外观仍 OOD，于是把这块视觉 shortcut 从 attention 删除。

不要误读成单一系统

它们方法上互补，但不是已经公开集成的端到端 stack。Cloak 的实验 policy 保留 source joint space，通过 tip FK/IK 转 target，并未直接使用 CalibAll/Qwen 的 camera-frame action。

其中 CalibAll 与 Qwen 最直接的共同点是 camera frame：前者解决“如何给旧数据补出这种 label”，后者解决“如何在 VLA action expert 中消费它并与视觉几何对齐”。Cloak 则指出，仅统一动作还不足够，观察本身也可能泄露本体身份。

4. 三种“统一”不是同一个词

4.1 Shape alignment

Padding 到 14D 或 80D 只让 tensor 能拼 batch。它不保证 slot 同义，也不保证 inactive dimension 不产生梯度。Qwen 的 binary mask 比简单 padding 多解决了一层监督问题。

4.2 Geometric alignment

CalibAll 的 $T^c_{tcp}$ 与 Qwen 的 camera-frame delta EEF 都在追求“画面里相同的运动，label 也接近”。前者更像数据编译器，后者还用 CaPE 把 camera geometry 注入 action attention。

4.3 Invariance by deletion

Cloak 不把不同末端外观映射到共同 latent，而是删除整块输入。这个设计在 end-effector pixels 对任务贡献小、对本体识别贡献大时特别有效；若接触判断必须看手指本身，删除会损失必要信息。

6. 一个可检验的联合假设

三篇工作合起来提出一个值得实验的假设：跨本体误差可拆成 label inconsistency、policy representation conflict、visual embodiment shortcut 与 controller/physics residual。可以做 $2\times2\times2$ 消融：raw vs camera-frame labels、unified vs per-embodiment policy、visible vs cloaked wrist EEF；再在相同 target robots 上比较。

预期但尚未被三篇共同验证：CalibAll/Qwen 类 camera action 与 Cloak 的 visual masking 可能互补，但 Cloak 删除 EEF pixels 后，camera-frame action 所需的精细 hand-eye relation 是否仍足够，必须用联合实验回答，不能从现有结果直接推出。

7. 最终判断

如果只记住一句话：跨本体 scaling 不是“把机器人名字写进 prompt”，而是把数据标签、动作几何、视觉观察与部署控制逐层去歧义。

CalibAll 最可立即复用；Qwen-RobotManip 给出最完整但最难复现的系统证据；Cloak 的 insight 最小巧，控制变量也最漂亮，但适用边界最明确。三者共同把 data process 从后台清洗工作推到了机器人 foundation model 的核心方法位置。
